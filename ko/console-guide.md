# 콘솔 사용 가이드

**Integration > EventBus > 콘솔 사용 가이드**

EventBus 콘솔에서 버스와 규칙을 만들고 관리하는 방법을 안내합니다. EventBus를 처음 사용한다면 버스 생성, 규칙 생성 순서로 진행합니다.

## 버스 생성하기

버스는 규칙을 묶어 관리하는 단위입니다. 커스텀 이벤트를 발행할 때는 버스를 지정합니다.

1. **버스 생성**을 클릭합니다.
2. 버스 정보를 입력합니다.
3. **확인**을 클릭합니다.

[스크린샷 - 버스 생성 화면]

| 항목 | 설명 |
|---|---|
| 이름 | 버스 이름입니다. 소문자로 시작하고 소문자, 숫자, 하이픈(-)만 사용하여 1~45자로 입력합니다. 프로젝트 안에서 중복될 수 없습니다. |
| 설명 | 버스 설명입니다. 최대 250자까지 입력할 수 있습니다. |
| 로그 연동 | Log & Crash Search로 이벤트 전달 로그를 보낼지 선택합니다. |

!!! tip "알아두기"
* 프로젝트당 버스를 최대 100개까지 만들 수 있습니다.
* 버스 이름은 생성 후 변경할 수 없습니다.

## 버스 관리하기

### 버스 조회

[스크린샷 - 버스 목록 화면]

버스 목록에서 버스를 클릭하면 버스 상세 정보를 확인할 수 있습니다. 상세 정보는 다음 탭으로 구성됩니다.

[스크린샷 - 버스 상세 화면(기본 정보 탭)]

| 탭 | 설명 |
|---|---|
| 기본 정보 | 버스 이름, 설명, 로그 연동 여부, 버스 키를 확인합니다. 버스 키는 커스텀 이벤트를 발행할 때 버스를 지정하는 데 사용합니다. |
| 규칙 | 버스에 등록된 규칙 목록을 확인합니다. |
| 모니터링 | 버스의 처리 이벤트 수, 전달 성공률, 전달 실패 수, 지연 시간 등의 지표를 확인합니다. |

[스크린샷 - 버스 상세 화면(모니터링 탭)]

### 버스 수정

버스 설명과 로그 연동 여부를 수정할 수 있습니다.

1. 수정할 버스를 선택합니다.
2. **수정**을 클릭합니다.
3. 설명 또는 로그 연동 여부를 변경합니다.
4. **확인**을 클릭합니다.

[스크린샷 - 버스 수정 화면]

### 버스 삭제

1. 삭제할 버스를 선택합니다.
2. **삭제**를 클릭합니다.
3. 확인 창에서 **확인**을 클릭합니다.

!!! danger "주의"
* 규칙이 등록된 버스는 삭제할 수 없습니다. 버스에 등록된 규칙을 모두 삭제한 뒤 버스를 삭제합니다.
* 여러 버스를 한 번에 삭제할 때 삭제할 수 없는 버스가 하나라도 있으면 모든 버스의 삭제가 취소됩니다.

## 규칙 생성하기

규칙은 이벤트 패턴, 대상, 재시도 정책을 묶은 설정입니다. 이벤트 패턴과 일치하는 이벤트를 지정한 대상으로 전달합니다.

규칙은 기본 설정, 이벤트 소스, 대상 설정, 재시도 설정 순서로 생성합니다.

1. 규칙을 추가할 버스를 선택합니다.
2. **규칙** 탭에서 **규칙 생성**을 클릭합니다.
3. 기본 설정을 입력한 뒤 **다음**을 클릭합니다.
4. 이벤트 소스를 설정한 뒤 **다음**을 클릭합니다.
5. 대상을 설정한 뒤 **다음**을 클릭합니다.
6. 재시도 정책을 설정한 뒤 **다음**을 클릭합니다.
7. 설정 내용을 확인한 뒤 **생성**을 클릭합니다.

[스크린샷 - 규칙 생성 설정 확인 화면]

### 기본 설정

[스크린샷 - 규칙 생성 기본 설정 화면]

| 항목 | 설명 |
|---|---|
| 이름 | 규칙 이름입니다. 소문자로 시작하고 소문자, 숫자, 하이픈(-)만 사용하여 1~45자로 입력합니다. 버스 안에서 중복될 수 없습니다. |
| 설명 | 규칙 설명입니다. 최대 250자까지 입력할 수 있습니다. |
| 활성화 | 규칙을 생성하자마자 사용할지 선택합니다. 기본값은 활성화입니다. |

### 이벤트 소스 설정

전달할 이벤트를 고르는 이벤트 패턴을 작성합니다. 이벤트 패턴은 폼 빌더 또는 JSON 편집기로 작성할 수 있습니다. JSON 편집기에서 사용하는 패턴 문법은 [이벤트 레퍼런스](./event-list/)를 참고합니다.

[스크린샷 - 규칙 생성 이벤트 소스 설정 화면(폼 빌더)]

[스크린샷 - 규칙 생성 이벤트 소스 설정 화면(JSON 편집기)]

| 항목 | 설명 |
|---|---|
| 소스 유형 | NHN Cloud 이벤트 또는 커스텀 이벤트를 선택합니다. |
| 서비스 | 이벤트가 발생하는 서비스를 선택합니다. |
| 이벤트 | 전달할 이벤트를 하나 이상 선택합니다. 서비스의 모든 이벤트를 전달하려면 전체를 선택합니다. |
| 필터 | 이벤트의 필드 값으로 조건을 추가합니다. NHN Cloud 이벤트는 `source`, `time`, `id`, `data` 필드를, 커스텀 이벤트는 `subject` 필드까지 조건으로 사용할 수 있습니다. |

### 대상 설정

이벤트를 전달할 대상을 추가합니다. 하나의 규칙에 대상을 최대 5개까지 추가할 수 있으며, 이벤트는 모든 대상에 병렬로 전달됩니다.

[스크린샷 - 규칙 생성 대상 설정 화면]

**Cloud Functions**

| 항목 | 설명 |
|---|---|
| 대상 프로젝트 | 함수가 있는 프로젝트를 선택합니다. |
| 함수 | 이벤트를 전달받아 실행할 함수를 선택합니다. |
| 서비스 계정 | 대상 프로젝트의 함수를 호출할 권한이 있는 서비스 계정을 선택합니다. |

**외부 HTTP**

| 항목 | 설명 |
|---|---|
| 엔드포인트 URL | 이벤트를 받을 HTTPS 주소를 입력합니다. 이벤트는 POST 메서드로 전송됩니다. |
| 인증 방식 | 인증 없음, API Key, OAuth 2.0 Client Credentials 중 하나를 선택합니다. |
| 요청 헤더 | 요청에 함께 보낼 헤더를 입력합니다. 최대 10개까지 추가할 수 있으며, 값은 최대 512자입니다. |

**알림**

| 항목 | 설명 |
|---|---|
| 수신 그룹 | 이벤트 요약을 받을 수신 그룹을 하나 이상 선택합니다. |

!!! tip "알아두기"
* 알림 대상은 규칙당 1개까지 추가할 수 있습니다. 여러 수신 그룹에 통지하려면 하나의 알림 대상에서 수신 그룹을 여러 개 선택합니다.
* 대상 유형은 대상을 추가한 뒤 변경할 수 없습니다.
* 외부 HTTP 대상의 인증 정보(API Key, Client Secret)는 저장한 뒤 다시 표시되지 않습니다.

### 재시도 설정

대상 서버의 일시적인 오류나 시간 초과로 전달에 실패하면 이벤트를 다시 전달합니다.

[스크린샷 - 규칙 생성 재시도 설정 화면]

| 항목 | 설명 |
|---|---|
| 재시도 기간 | 처음 전달에 실패한 시점부터 재시도할 기간입니다. 시간, 분, 초 단위로 최대 24시간까지 설정할 수 있습니다. 기본값은 24시간입니다. |
| 재시도 횟수 | 최대 재시도 횟수입니다. 0~185회로 설정할 수 있습니다. 입력하지 않으면 재시도 기간 동안 횟수 제한 없이 재시도합니다. |

!!! tip "알아두기"
* 버스당 규칙을 최대 300개까지 만들 수 있습니다.
* 이벤트는 최소 한 번 이상(at-least-once) 전달되며 전달 순서는 보장되지 않습니다. 같은 이벤트가 중복 전달될 수 있으므로 대상에서는 이벤트 ID(`id`)로 중복을 처리하는 것이 좋습니다.

## 규칙 관리하기

### 규칙 수정

규칙 이름을 제외한 설정을 수정할 수 있습니다.

1. 수정할 규칙을 선택합니다.
2. **수정**을 클릭합니다.
3. 변경할 항목을 수정합니다.
4. **저장**을 클릭합니다.

### 규칙 활성화와 비활성화

규칙을 삭제하지 않고 이벤트 전달만 멈추거나 다시 시작할 수 있습니다.

1. 규칙을 선택합니다.
2. **활성화** 또는 **비활성화**를 클릭합니다.

[스크린샷 - 버스 상세 화면(규칙 탭)]

### 규칙 삭제

1. 삭제할 규칙을 선택합니다.
2. **삭제**를 클릭합니다.
3. 확인 창에서 **확인**을 클릭합니다.

!!! danger "주의"
* 다른 사용자가 먼저 수정한 규칙은 저장할 수 없습니다. 규칙을 다시 불러온 뒤 수정합니다.
* 여러 규칙을 한 번에 삭제할 때 삭제할 수 없는 규칙이 하나라도 있으면 모든 규칙의 삭제가 취소됩니다.
