# EventBus 개요

**Integration > EventBus > 개요**

EventBus는 NHN Cloud 서비스와 사용자 애플리케이션에서 발생한 이벤트를 받아 규칙에 따라 원하는 대상으로 전달하는 이벤트 라우팅 서비스입니다.

사용자는 별도의 코드 없이 이벤트 패턴과 대상만 지정하여 서비스 간 이벤트 기반 자동화를 구성할 수 있습니다. 예를 들어 Object Storage에 파일이 업로드되면 Cloud Functions로 썸네일을 생성하거나, 인스턴스 상태가 변경되면 담당자에게 알림을 보낼 수 있습니다.

모든 이벤트는 CNCF 표준인 CloudEvents 형식으로 전달되며, 전달에 실패한 이벤트는 설정한 재시도 정책에 따라 자동으로 다시 전달됩니다.

이 문서에서는 EventBus의 서비스 아키텍처와 주요 기능, 서비스 접근 경로, 서비스 용어를 안내합니다.

## 서비스 아키텍처

![[그림1] EventBus 서비스 아키텍처](이미지 제작 필요 -> 하단의 이미지 초안 참고)

1. 이벤트 수신: NHN Cloud 서비스 또는 사용자 애플리케이션에서 발생한 이벤트가 EventBus로 전달됩니다.
2. 규칙 평가: 버스에 등록된 규칙의 이벤트 패턴과 이벤트를 비교합니다. 여러 규칙과 일치하면 각 규칙에 따라 전달합니다.
3. 이벤트 전달: 일치한 규칙의 대상으로 이벤트를 전달합니다. 전달에 실패하면 재시도 정책에 따라 다시 전달합니다.

## 주요 기능

* **이벤트 수집**
    * NHN Cloud 서비스에서 발생한 이벤트를 별도 설정 없이 수신합니다.
    * 사용자 애플리케이션은 이벤트 발행 API로 커스텀 이벤트를 발행할 수 있습니다. 이벤트를 1건씩 발행하거나, 한 번의 요청에 최대 10건을 묶어 발행할 수 있습니다.
* **규칙 기반 라우팅**
    * 이벤트의 소스, 유형, 데이터 값을 조건으로 하는 이벤트 패턴을 작성하여 원하는 이벤트만 골라낼 수 있습니다.
    * 정확히 일치, 접두사, 접미사, 제외, 존재 여부, 숫자 범위 조건을 지원합니다.
    * 콘솔의 폼 빌더 또는 JSON 편집기로 패턴을 작성할 수 있습니다.
* **다양한 대상으로 전달**
    * 하나의 규칙에 최대 5개의 대상을 지정할 수 있으며, 이벤트는 모든 대상에 병렬로 전달됩니다.
    * 다음 대상을 지원합니다.
        * **Cloud Functions**: 함수를 실행합니다.
        * **외부 HTTP**: 사용자가 지정한 HTTPS 엔드포인트로 이벤트를 전송합니다. API Key, OAuth 2.0 Client Credentials 인증을 사용할 수 있습니다.
        * **알림**: 수신 그룹에 Email, SMS 등으로 이벤트 요약을 통지합니다.
* **자동 재시도**
    * 대상 서버의 일시적인 오류나 시간 초과로 전달에 실패하면 지수 백오프 방식으로 다시 전달합니다.
    * 규칙마다 재시도 기간(최대 24시간)과 재시도 횟수(최대 185회)를 설정할 수 있습니다.
* **모니터링**
    * 버스별로 처리 이벤트 수, 전달 성공률, 전달 실패 수, 지연 시간 등의 지표를 확인할 수 있습니다.
    * Log & Crash Search를 연동하면 이벤트 전달 로그를 확인할 수 있습니다.

## 제한 사항

| 항목 | 제한 |
|---|---|
| 프로젝트당 버스 수 | 100개 |
| 버스당 규칙 수 | 300개 |
| 규칙당 대상 수 | 1~5개 |
| 이벤트 발행 요청당 이벤트 수 | 10건 |
| 이벤트 발행 요청 크기 | 1MB |
| 재시도 기간 | 최대 24시간 |
| 재시도 횟수 | 0~185회 |

## 서비스 접근 경로

NHN Cloud 콘솔에서 Integration > EventBus를 선택하여 서비스에 접근할 수 있습니다.

## 서비스 용어

| 용어 | 설명 |
|---|---|
| 규칙 | 이벤트 패턴과 대상, 재시도 정책을 묶은 설정입니다. 이벤트 패턴과 일치하는 이벤트를 대상으로 전달합니다. |
| 대상 | 이벤트를 전달받는 서비스 또는 엔드포인트입니다. |
| 버스 | 규칙을 묶어 관리하는 단위입니다. 커스텀 이벤트는 버스를 지정하여 발행합니다. |
| 이벤트 | 리소스 상태 변경 등 시스템에서 발생한 변화를 나타내는 데이터입니다. CloudEvents 형식을 따릅니다. |
| 이벤트 소스 | 이벤트가 발생한 출처입니다. NHN Cloud 이벤트와 커스텀 이벤트로 구분합니다. |
| 이벤트 패턴 | 전달할 이벤트를 골라내는 조건입니다. |
| CloudEvents | 이벤트 데이터를 공통된 형식으로 기술하기 위한 CNCF(Cloud Native Computing Foundation) 표준 규격입니다. |
